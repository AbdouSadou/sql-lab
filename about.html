A browser-only SQL workspace for teaching

About

is a place to write and run SQL for learning and teaching. It runs entirely in your browser: the queries you write and the data you open are never sent anywhere.

What you can do here

  • Practise on built-in datasets. Pick one from the database menu at the top of the page and start writing queries, or start from one of the sample queries offered where the result appears: choosing one puts it in the editor, and nothing runs until you press Run. The Schema tab of the sidebar lists its tables and columns, and a click puts a name in your query.
  • Work through exercises that check themselves. Choose an exercise set in the Exercises tab of the sidebar, write your query and press Check answer. You are told whether your result matches, and if not, what differs: when a row differs, the expected rows and yours are shown side by side, with the cells that differ outlined. Hints appear one at a time when you ask for them, and Previous and Next move through the set.
  • Share a query. Copy link, at the top, makes a link that opens the same dataset (and exercise) with your query in the editor. The query travels inside the link itself; nothing is stored on a server.
  • Keep evidence of your work. Every query you run is written to a run log; the History tab of the sidebar lists it, and a click puts an earlier query back in the editor. Export, then Evidence, saves the log as a text file with your student number and a checksum, so you can attach it to assessed work and a marker can see it has not been edited. The file covers the dataset that is open, so export once for each dataset you worked on. The log is kept in this browser on this device, so on a shared computer export it before you log off, and note that a private window starts with an empty log. Times in the history list are UTC.
  • Use your own data. Open a SQLite database file or a SQL script from the database menu, and save the database, with your changes, as a file (Export, then Database; the name you give it there also renames it on the page).

For markers

To check an evidence file, open the check page and paste the file or drop it on the page. It says VALID or EDITED without uploading anything. A file lists the queries run on one dataset only (its dataset: line), so ask a student who worked on two datasets for two files. The checksum shows the file was not changed after it was exported; it does not prove who ran the queries.

A full database in the browser

The database engine is SQLite, compiled to WebAssembly. It supports indexes, triggers, views, transactions, CTEs, window functions and execution plans. Each page you open starts with its own in-memory database, so you can experiment freely: reloading the page or clicking the logo gives you a clean slate.

Your own data stays with you

Open a SQLite database file or a SQL script from your computer and it is read by your browser only. There is no server, no account, no analytics and no cookies.

Some things are remembered between visits, in your browser's local storage on your own device and nowhere else: the last query you ran for each database, which exercises you have passed, the SQL you last wrote for each exercise, your run log (up to 200 queries for each dataset, fewer if they are very long), the theme and the text size you chose, and the sizes you gave the panes (and whether the sidebar is hidden). If your browser has no room left, the page says so, and whatever could not be saved is lost when you close it. The Reset progress button in an exercise set clears that set's passes and saved SQL. Clearing your browser's site data clears everything. Your student number is used only to write the evidence file; it is never stored.

On a projector, a tablet or a phone

A− and A+, at the right of the toolbar above the editor, make the SQL and the results smaller or larger, from 12 to 24 pixels, so they can be read from the back of a room. The size is remembered.

On a narrower screen the sidebar (Schema, Exercises and History) opens over the page from the Sidebar button at the top, and closes again with Close, Escape or a press beside it. On a phone the query and its result are two views, Editor and Result, and running a query shows its result; Copy link, Export, Theme and Help are in the More menu (the three dots), and Run is at the bottom of the screen. Everything needed to write a query and read its result is there without a keyboard shortcut.

Keyboard shortcuts

Ctrl Enter
Run the query, or the part of it you selected (only while the cursor is in the editor)
Ctrl Shift Enter
Check your answer (when an exercise is open)
Ctrl /
Comment or uncomment the line (in the editor)
Ctrl Space
Suggest table, column and function names (in the editor)
Ctrl O
Open a database file
Ctrl U
Open a database from a URL

In the editor, Tab indents. To move the focus out of the editor with the keyboard, press Esc and then Tab (or Shift Tab to go back).

The editor suggests names as you type: the tables, views and columns of the open database, and SQLite's keywords and functions. Pick one with the arrow keys and press Enter (until you pick one, Enter starts a new line); Esc closes the list.

The bars between the sidebar and the query, and between the query and its result, can be dragged, or reached with Tab and moved with the arrow keys. Enter on the sidebar's bar hides or shows the sidebar.
